# 🛰️ Orbital Guard

Interactive **space-debris collision-avoidance decision-support** system.

Open the command center, pick a threat scenario, press **START SIMULATION**, and watch the ground pipeline + edge ranker + safety gate decide whether the asset dodges — or residual risk remains.

Built by **Team Nicotech** (PS-02 / NX-77 lineage).

## 🚀 What is Orbital Guard?

Orbital Guard is a **simulation / research** decision-support prototype for LEO conjunctions:

1. **Ground analysis** builds a fixed table of maneuver candidates (including “do nothing”).
2. A **~74 KB GBDT edge ranker** selects among those candidates in ~1–2 ms (lab CPU).
3. A **deterministic safety gate** accepts the edge pick or falls back to ground logic.
4. The **web command center** visualizes the conjunction on a Three.js Earth scene and shows the full decision trace.

It is **not** flight software and does **not** produce official NASA CARA collision probability.

---

## 🎯 The Problem

Low Earth Orbit is crowded. Active satellites and debris can pass within kilometers (or less) of each other at ~7–8 km/s. Operators need tools that:

- detect close approaches (conjunctions),
- estimate risk,
- propose fuel-aware avoidance burns,
- and keep a verifiable safety check between any fast “edge” suggestion and the final action.

Orbital Guard studies that **ground → edge → gate** loop end-to-end on deterministic demo scenarios.

## 💡 How Orbital Guard Works

```
Demo scenario (HIGH_RISK / LOW_COST / AMBIGUOUS / NO_MANEUVER)
        │
        ▼
Ground service  →  candidates + optimal score  →  edge GBDT ranks list
        │                                              │
        └──────────── safety gate (miss threshold) ────┘
                              │
                              ▼
                    final decision + explanation
                              │
                              ▼
              Command Center UI (risk panel, table, outcome)
```

- **Website feature** → calls `POST /api/run` (or static `demo_results.json`).
- **Service** → `backend.service.run_scenario`.
- **Propagation / screening / risk / maneuvers** → Python modules under `backend/`.
- **Edge ranker** → `edge/inference/predict.py` + `models/edge/gbdt.joblib`.

## 🖥️ Explore the Website

### Opening sequence

| What you see | What it is |
|---|---|
| Boot bar (“INITIALIZING SENSOR ARRAY” …) | Cinematic load of the Three.js scene |
| Title screen **SPACE DEBRIS COLLISION AVOIDANCE** | Mission home |
| **START MISSION →** | Enters the command center |

### 3D orbital scene

| Element | Meaning |
|---|---|
| Textured Earth + clouds | Reference body (LEO frame) |
| Cyan orbital ring / satellite model | Protected asset (DEMO-SAT-01 / ISS-like) |
| Colored debris markers | Visual stand-ins for the four demo scenarios |
| Debris field points | Ambient tracked-object field (visual only) |

Controls: mouse parallax on the globe; camera presets **GLOBAL / ASSET / THREAT**; pause/resume simulation time.

### Left panel — Mission console

**OVERVIEW**  
Protected asset card: name, NORAD ID, object type, active scenario, mode (`OFFLINE DEMO`).

**THREATS**  
Four selectable demo scenarios:

| Scenario | UI label | Intent |
|---|---|---|
| `HIGH_RISK` | HIGH | Close approach, high screening risk |
| `LOW_COST` | MED | Moderate miss; low-Δv preference |
| `AMBIGUOUS` | MED | Borderline geometry |
| `NO_MANEUVER` | LOW | Wide miss; do-nothing is correct |

**SATELLITE / SYSTEM**  
Orbital profile and processing-core labels (propagator SGP4/SDP4, screening active, simulation mode).

### Right panel — Threat response

| UI field | Source |
|---|---|
| Est. collision probability | `risk.approx_collision_risk_estimate` (screening estimate) |
| Risk status bar | `risk.risk_status` + `risk_score_0_1` |
| Miss distance | `conjunction.miss_distance_km` |
| Time to TCA | `conjunction.time_to_tca_min` |
| Relative speed | `conjunction.relative_speed_km_s` |
| Edge action / confidence / latency | `edge.*` |
| Safety gate PASS/FAIL | `safety_gate.passed` |
| Fallback flag | `fallback.activated` |
| Final decision | `final_decision.*` |
| Candidate table | `candidates[]` (Δv, new miss, safety flag, ground-optimal ★) |

Threat-level pills (**CRITICAL / ELEVATED / MODERATE / LOW**) map 1:1 to the four scenarios.

**▶ START SIMULATION →** runs the pipeline for the selected scenario and drives the outcome banner (dodge vs residual collision risk / explosion sequence when the gate cannot clear a safe miss).

## 🧭 Technical Walkthrough

### Step 1 — Use the website

Open the GitHub Pages URL (or serve `frontend/` with any static file server).

Select a threat → **START SIMULATION** → read risk numbers, candidate table, edge pick, gate, final decision.

### Step 2 — Trace the response schema

📖 `docs/FRONTEND_INTEGRATION.md`  
Every field the UI reads is documented there (`target`, `threat`, `conjunction`, `risk`, `candidates`, `ground`, `edge`, `safety_gate`, `fallback`, `final_decision`).

### Step 3 — Call the same logic from Python

```bash
cd Orbital-Guard
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
PYTHONPATH=. python run_demo.py --scenario HIGH_RISK
```

Or programmatically:

```python
from backend.service import run_scenario, list_demo_scenarios
print(list_demo_scenarios())
print(run_scenario("HIGH_RISK")["final_decision"])
```

### Step 4 — Optional live HTTP API

```bash
pip install fastapi uvicorn
PYTHONPATH=. python api_server.py
# → http://127.0.0.1:8000
```

| Method | Path | Role |
|---|---|---|
| `GET` | `/` | Serves `frontend/index.html` |
| `GET` | `/api/health` | Health check |
| `GET` | `/api/scenarios` | Demo keys |
| `POST` | `/api/run` | Body `{"scenario":"HIGH_RISK","confidence_threshold":0.35,"min_acceptable_miss_km":0.5}` |

Point a hosted UI at this API with `window.ORBITAL_GUARD_API`.

### Step 5 — Refresh static demo data (for Pages)

After changing scenarios or models:

```bash
PYTHONPATH=. python -c "
from backend.service import run_scenario
import json
from pathlib import Path
out = {k: run_scenario(k) for k in ['HIGH_RISK','LOW_COST','AMBIGUOUS','NO_MANEUVER']}
for r in out.values():
    if 'edge' in r: r['edge']['model_path'] = 'models/edge/gbdt.joblib'
Path('frontend/data/demo_results.json').write_text(json.dumps(out, indent=2))
print('updated frontend/data/demo_results.json')
"
```

Commit the JSON so GitHub Pages stays in sync with the backend.

## 🧮 Algorithms

| Website feature | What the user sees | Underlying logic | Code |
|---|---|---|---|
| Scenario list | HIGH_RISK … NO_MANEUVER nodes | Fixed deterministic demos | `backend/scenarios/demo_scenarios.py` |
| 3D asset / debris motion | Orbiting markers | Visual only (Three.js) | `frontend/index.html` |
| Miss distance / TCA / relative speed | Right-panel telemetry | Propagation + conjunction geometry | `backend/propagation/sgp4_engine.py`, `backend/conjunction/` |
| Collision probability % | Large risk number + bar | Approximate screening Pc + 0–1 score | `backend/risk/risk_model.py` |
| Candidate table | Δv, new miss, safety, ★ | Fixed action space + first-order burn sim + score | `backend/scenarios/action_space.py`, `backend/maneuver/` |
| Edge action + confidence | Ranked pick, ms latency | GradientBoostingClassifier on compact features | `edge/inference/predict.py`, `models/edge/gbdt.joblib` |
| Safety gate / fallback | PASS/FAIL, fallback flag | Deterministic miss threshold check | `backend/service.py` |
| Outcome banner | DODGED / DESTROYED | UI interpretation of final decision + residual risk | `frontend/index.html` (`applyResult`, `showOutcome`) |
| START SIMULATION | Full decision trace | `run_scenario` end-to-end | `backend/service.py` ← `POST /api/run` or static JSON |

Deeper phase notes:

- Phase 1 pipeline — `docs/PHASE_1.md`, `run_simulation.py`
- Edge train / benchmark — `docs/PHASE_2.md`, `run_phase2.py`
- Failure analysis — `docs/PHASE_3.md`, `docs/EDGE_FAILURE_ANALYSIS.md`
- System map — `docs/ARCHITECTURE.md`

## 🔗 How Everything Connects

```
frontend/index.html
    │  fetch POST /api/run   OR   fetch data/demo_results.json
    ▼
api_server.py  (optional live host)
    │
    ▼
backend/service.run_scenario
    ├─ demo_scenarios.build_demo_scenarios()
    ├─ ground candidates (maneuver sim + score)
    ├─ edge/inference/predict.EdgeModel  (gbdt.joblib)
    └─ safety_gate + fallback → final_decision
```

Static Pages path skips `api_server.py` but still shows **real** service outputs baked into `frontend/data/demo_results.json`.
